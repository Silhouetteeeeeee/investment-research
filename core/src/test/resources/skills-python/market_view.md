大盘怎么看：指数、宽度、量能与操作节奏

判断标准：指数涨跌只是结果，先看三件事——市场宽度（涨跌家数、涨跌停）、量能（成交额与近期均量）、结构（哪些板块在涨、是否扩散）。指数可能被权重股拉红而多数股票在跌，也可能指数下跌但宽度健康。只报指数涨跌就下结论，是不合格的。

第一步：确认时点。工具返回 as_of 与 session：盘前、盘中、午间休市、收盘或最近交易日。盘中数据还会变，要写明“截至 HH:MM”；非交易日写“最近交易日”，不要把上一交易日的数据说成今天。

第二步：按顺序读事实，每条都引用来源：
1. 指数：主要指数涨跌幅与成交额；权重（上证50/沪深300）与中小盘（中证500/中证1000）、成长（创业板/科创50）的相对强弱，判断是普跌、结构性分化还是普涨。
2. 宽度：上涨/下跌/平盘家数、涨停/跌停与真实涨停/跌停、活跃度。上涨家数占比低于 40% 说明多数股票在跌；涨停与跌停的对比反映短线情绪。
3. 量能：两市成交额（截至时点）与按当前节奏折算的全天量能相对近 20 日均量的比例。放量上涨、缩量上涨、放量下跌的含义不同；盘中折算只是估算，必须标明。
4. 趋势：上证、深证、创业板、沪深300 相对 MA5/MA10/MA20/MA60 的位置、近 5 日/20 日涨跌、20 日高低点。均线按已完成日线计算；站上或跌破 MA20/MA60 是判断中期节奏的事实，不是对未来的预测。
5. 结构：涨幅前列与跌幅前列行业、行业上涨/下跌家数、净流入、领涨股。判断是普涨、轮动、还是少数板块抱团；领涨板块的成交额与上涨家数是否同步，能区分真扩散与个别股票拉动。
6. 情绪：涨停家数、最高连板、连板分布、涨停行业集中度。连板高度下降、跌停增加、炸板增多，通常说明风险偏好在回落。
7. 消息面：只引用与指数或板块异动明确相关的快讯标题；不相关的不提，也不要把单条新闻当成趋势。

第三步：读取工具给出的 data.state。规则引擎已经按趋势、宽度、量能、波动、结构五项打分，你负责解释，不要另起一套判断：
- state 只有四档：强势 / 震荡 / 弱势 / 极端风险。回答时原样使用，不要改写成“偏强/偏弱”，也不要用“牛市/熊市”替代。
- basis 是判断依据：挑最关键的两三条，把读数、方向和分数说清楚，并引用对应来源。不要只复述结论。
- risk_level 是风险等级（低/中/高/极高）；confidence 是数据完整度带来的置信度；missing 非空时明确说哪些数据缺失。
- invalidation 是判断失效条件，必须写进回答和操作建议，不能省略。
- 如果你读到的信号与 state 冲突，先写规则结论，再写你看到的矛盾；不要静默改档。信号不一致时直接写“信号不一致”。

第四步：操作建议只给“仓位与节奏”，不给个股买卖指令：
- 用条件式表达：“若 X 成立，仓位可维持在中性偏高；若 Y 发生，降到中性或等待”。可以用轻仓/中性/重仓描述相对状态，不给精确仓位比例。
- 至少给三个可观察的触发条件，例如：上证跌破 MA20、上涨家数占比连续低于 40%、两市成交额跌破近 20 日均量的 80%、跌停家数明显增加、领涨板块次日不能延续。
- 区分持有周期：短线看情绪与量能，中线看 MA20/MA60 与宽度。不要用一天的盘面替代中期判断，也不要用中期趋势否定当天的风险信号。
- 结尾写明“以上是盘面事实与情景推演，不构成投资建议”。

回答结构：
1. 一句话结论（强势/震荡/弱势/极端风险 + 风险等级 + 最重要的一条依据）。
2. 盘面事实：指数、宽度、量能、趋势、结构、情绪、消息面，可用小标题或表格。
3. 判断依据与失效条件：state.basis 的关键读数，以及 state.invalidation 里的具体条件。
4. 矛盾与不确定：哪些信号互相打架，哪些数据缺失或只是盘中估算。
5. 情景与操作节奏：三档情景 + 触发条件 + 观察指标 + 风险提示。

取数：调用 get_market_overview 一次即可，不需要公司参数；返回的 data.state 就是模块 1 的结论。用户同时问某家公司时，另外加载对应公司 skill、用公司工具取数，大盘与个股分开说清楚。数据缺失时写「资料不足」，不要用记忆里的点位、成交额或新闻补位。

禁止：
- 只报指数涨跌，不看宽度、量能与结构。
- 把盘中数据当成收盘数据，或不写时点。
- 不预测具体点位，也不给“明天必涨/必跌”式判断。
- 推荐具体个股、给出个股买卖价或精确仓位比例。
- 把单条新闻、单个板块的涨停当成大盘趋势。
- 用“牛市/熊市”口号代替证据。
- 对缺失的数据编造数字。
