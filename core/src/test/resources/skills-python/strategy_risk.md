策略与风险管理：条件下的操作预案与仓位上限

判断标准：仓位不是由“感觉市场好不好”决定的，而是由市场状态、风险等级、你能承受的回撤和当前持仓共同决定。任何操作建议都必须带触发条件，否则只是情绪表达。

第一步：先确认市场状态。优先用本轮已经取到的 data.state（强势/震荡/弱势/极端风险）与 risk_level；没有就先调 get_market_overview。不要自己重新判断状态，也不要用“牛市/熊市”这类口号。

第二步：确认用户约束。向用户要三项信息，缺一项就在回答里标明并降低结论强度：
- 风险承受能力：保守 / 稳健 / 积极。
- 当前总仓位（股票类资产占总资产的比例）。
- 当前现金比例；有具体持仓时一并提供代码、占比、成本价。
用户没有提供时不要替他假设一个具体仓位，只给区间与条件。

第三步：调用 build_strategy_plan，把 market_state、risk_level、risk_tolerance、position_pct、cash_pct、holdings 一起传进去。看这些输出：
- caps：总仓位上限、单只上限、现金下限、止损比例。上限是硬约束，不是目标仓位。
- stance：降低风险 / 持有不加仓 / 观望 / 研究买入（分批）。
- actions：每个动作都带 condition，回答时原样保留条件。
- holdings：超配、浮亏触线、止损价。
- raise_conditions / lower_conditions：什么情况下可以上调或下调一档。

第四步：把结论写成条件式，而不是指令式：
- 观望：写清“等什么出现再做”，例如指数站上20日均线、上涨家数占比连续回升、轮动出现持续强势方向。
- 持有：写清“什么情况下改变决定”，例如跌破止损、指数跌破20日均线、个股逻辑失效。
- 研究买入：只能分批，写清第一批上限、第二批的触发条件，并说明优先选什么（估值不处于历史高位、基本面可验证）。
- 降低风险：写清先减什么（跌破止损、超配、逻辑失效），减到多少，现金补到多少。

第五步：风险纪律要说清楚：
- 单只止损：按 caps.stop_loss_pct，弱势与极端风险市场更紧。
- 组合层面：总仓位不超过 caps.total_pct，现金不低于 caps.cash_floor_pct。
- 超配：单只超过 caps.single_pct 就要降下来。
- 止损上移与下移都要有规则，不能因为“再等等”把止损挪低。

回答结构：
1. 一句话结论：当前该是什么姿态（降低风险 / 持有 / 观望 / 研究买入），仓位上限多少。
2. 市场状态与依据：状态、风险等级、关键依据（趋势、宽度）。
3. 你的约束：风险承受能力、仓位、现金、持仓情况；缺失项要写明。
4. 操作预案表：动作、触发条件、具体做法。
5. 仓位与止损：总上限、单只上限、现金下限、止损比例与执行方式。
6. 上调/下调条件：什么情况下可以加一档，什么情况下必须降一档。
结尾写“以上是按规则生成的情景式预案，不构成投资建议”。

禁止：
- 给出“满仓”“清仓”这类无条件结论。
- 在没有仓位信息时编造具体仓位数字。
- 用“必涨”“稳赚”“抄底”这类说法。
- 忽略用户的风险承受能力，给出一刀切的仓位。
- 把仓位上限当成目标仓位，鼓励用户顶格持有。
